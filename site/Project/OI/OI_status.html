관련 workspace: F:\workspace\OI_status

요약

  • OI의 브랜드 방향과 통합 기획을 기능·화면·데이터 구조와 기술 구현으로 구체화하는 OI Status 개발 프로젝트다.
  • OI는 성공 공식이나 의지 훈련이 아니라, 멈춘 사람이 실패를 해석하고 피드백 가능한 첫 행동으로 다시 움직이게 돕는 시작 동행 브랜드다.

역할과 경계

  • OI_status는 사용자의 실행·배움·피드백·재시작 흔적을 보여 주는 단독 웹앱과, 메인 상품을 뒷받침하는 핵심 디지털 서비스를 개발한다.
  • 메인 1:1 진단·30일 동행을 팀이 공동 운영하거나 복제하지 않는다.
  • 모든 아이템에는 피드백 가능한 최소 결과물과, 실행하지 못했을 때 더 작은 행동으로 돌아가는 재시작 장치가 있어야 한다.

현재 결정

  • 제품의 세 기능은 Library(원본·PARA 맥락·관계), Supporter(첫 기록·맥락 보완·재시작 질문), Status(근거 있는 현재 상태)다. 같은 기록이 세 기능을 거쳐 나중의 행동이나 결과물에 다시 쓰이는 흐름을 지향한다.
  • 공개 기억에는 원칙·결정·재사용 가능한 학습만 남기며, 고객별 원문과 민감한 운영 정보는 workspace의 .private에 분리한다.
  • 이전에는 원본을 각 기기·Drive에 두고 링크만 공유하는 방향을 검토했다. **2026-10-28 첫 버전 방향은 PC·모바일에서 허락한 범위의 원본과 변화를 PC 개인 저장소에 모으고, Library가 PARA 맥락에 연결하는 것**이다. Drive 원본의 복제·갱신 정책은 아직 결정하지 않았다. Project와 Area는 별도 공간이다.
  • 첫 구상은 Notion·Obsidian의 전체 연동이나 공개 템플릿 생태계를 완료 조건으로 두지 않는다. 로컬 AI 처리와 일회성/부분 유료화는 기술·사업 가설로 남긴다.
  • OI Status는 상담·동행을 대체하지 않고 기록과 재시작을 뒷받침하는 핵심 디지털 서비스이며, 단독 웹앱으로도 사용 가능해야 한다.
  • RPG의 스태이터스 창·가이드 요정·한계돌파·스토리 표현은 세 기능의 기본 순환을 교체하지 않는다. 사용자별 목표와 근거 있는 스탯을 보여주고, 실제 목표의 도전과 선택적 이야기 결과물로 연결하는 경험·소구 방향이다.
  • Library에 PARA를 차용하는 이유는 **기록을 한 맥락으로 묶는 기준이 OI Status의 목적과 잘 맞기 때문**이다. 사용자의 실제 Obsidian 폴더를 그대로 복제하는 것이 아니다. Project는 진행 중인 목표·산출물, Area는 계속 관리할 책임·루틴, Recource는 다시 쓰는 지식, Archive는 종료·비활성 맥락에 가깝다. Project와 Area는 독립 공간이며, 원본과 주제 허브는 필요한 관계만 링크로 연결한다.
  • 기록의 수집·추출·정리·표현은 사용자가 적어둔 CODE 흐름과도 연결된다. 사용자의 기존 저장소에 미분류·예외 노트가 있는 것과 PARA 기준을 제품에 쓰는 결정은 별개다. 앱은 보류·수정 가능성을 두되, 자동 연결의 판정 기준과 확정 권한은 설계·검증해야 한다.
  • AI 처리는 PC 중심으로 설계한다. 사용자가 PARA Project의 맥락과 실제 로컬 작업 폴더를 연결해 Codex와 첫 결과물을 만드는 흐름을 검토한다. PARA Project와 물리적 폴더는 다른 역할이며, Codex 인계 방식은 아직 정하지 않았다. 기획 기록: F:\workspace\OI_status\docs\planning\2026-10-27_PARA_분류_기준과_PC_프로젝트_시작.md.

첫 버전의 새 기준 — 2026-10-28

  • 1차 목표는 **기록 경험의 재설계**다. 사용자가 평소처럼 활동하면 생기는 파일·변화를 기록의 출발점으로 삼고, 별도 일지 작성과 사후 정리의 수고를 줄인다.
  • Library는 원본·변화·출처·PARA 관계를 보존하고 나중에 바로 찾고 활용하게 한다. Supporter는 확인 가능한 흔적으로 기록 초안을 만들고, 부족한 맥락만 짧게 묻는다. 이 둘의 결합이 첫 버전의 완료 기준이다.
  • Status의 RPG 경험은 이 기반 위에서 검증할 후속 기능이다. 추후 근거로 활용할 수 있게 출처·변화·사용자 확인 여부는 처음부터 구분한다.
  • 설계 초안: F:\workspace\OI_status\docs\planning\2026-10-28_OI_Status_첫_버전_Library_Supporter_기능_설계_초안.md. 모바일 수집 범위·PC 원본 보관 정책·동기화 방식은 구현 전 확인할 결정이다.
  • PC MVP는 **Python+PySide6 로컬 설치 앱**을 현재 추천안으로 둔다. 파일 수집·문서 해석·PARA·Supporter·로컬 AI 연계를 PC에서 처리하고, 모바일은 이후 별도 로컬 앱으로 개발한다. 두 앱은 기록·변화·동기화 규약을 공유한다. 개인 폴더 수집과 로컬 AI 모델 설치는 수집 동의 흐름을 정한 뒤 진행한다. 비교 문서: F:\workspace\OI_status\docs\planning\2026-10-28_PC_MVP_기술_구성_제안.md.
  • 최신 첫 버전 방향에서는 Drive를 PC 원본의 모바일 접근을 위한 후속 수단으로 두고, PC의 원본 수집·기록 생성·PARA 연결·나중의 활용을 우선한다. 다운로드·문서 폴더는 첫 실행에서 선택된 기본 후보로 제시하되 사용자의 명시적 동의를 받은 뒤 하위 폴더까지 수집한다. 로컬 AI는 기록 생성과 Project 기준 분류·생성, 부족한 맥락 질문을 맡는다.
  • PC 원본 저장소와 기기별 로컬 DB, 변경 내용 동기화의 구조는 F:\workspace\OI_status\docs\planning\2026-10-28_PC_모바일_공유_DB_구조_초안.md에 정리했다. 원본 바이트와 추출 텍스트, 관찰된 변화, AI 제안, 사용자 답변을 구분한다.
